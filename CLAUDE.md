# lunes-lti

LTI 1.3 connector between an LMS (Moodle first) and the Lunes web app. Part of a master's thesis prototype; the
decision and the requirements mapping are in ADR 0013 of the lunes-app repository
(`lunes-app/docs/web/0013-lti-connector-service.md`). New decisions are recorded as ADRs there, not in this repository.

## Fixed decisions

- Python (>= 3.11), Flask, PyLTI1p3. SQLite through the standard library for state, nonce and launches.
- Runs on the host of the web app below `/lti/` (same origin as the app). In development the webpack dev server of
  lunes-app proxies `/lti` to this service.
- The tool's key pair and the token secret are generated by the service at runtime in its data directory, never
  committed.
- Data minimisation: per launch only pseudonymous IDs (`sub`, context, resource link, AGS line item) and the selected
  job and unit. Never names or e-mail addresses.
- The app gets a short-lived session token in the URL fragment of the redirect.

## Working rules (Nortal policy)

- Claude does not commit, merge, rebase or push. It proposes commit messages (English, imperative mood).
- Claude does not add, install or upgrade dependencies. It proposes the exact pip command; the developer runs it.
- Claude does not read or generate cryptographic keys, `.env` files, `config.toml` or the data directory.
- Small steps, each with a check (`pytest` plus a manual launch).
